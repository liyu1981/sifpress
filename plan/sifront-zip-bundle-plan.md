# Plan — Sifront ZIP bundle + admin "Update sifront"

A sifront was a single self-contained HTML file (`dist/<name>.sifront`) with
every stylesheet, script and font inlined, stored as text in `sifronts.content`
and served verbatim. This plan re-packages a sifront as a **ZIP container** with
two entries — `meta.json` (identity + version + theme keys) and `bundle.js`
(the raw app JS bundle) — and adds an admin button to replace an existing
sifront with a newly built bundle.

The **admin UI unpacks the ZIP in the browser with JSZip** and posts the two
pieces to the JSON API, so the backend carries **no zip dependency**: it just
stores `bundle`/`meta`/`version` columns.

Related: `plan/sifront-theme-kv-config.md` (`meta.json` `require_keys`),
`plan/version-check-and-update.md` (version/manifest conventions for the PHP
artifact).

---

## 1. Goals

1. Define `.sifront` as a ZIP with exactly `meta.json` + `bundle.js`.
2. `buildfront.php` emits that ZIP and bakes the sifront's **version** (from
   `package.json`) into `meta.json`.
3. Unpack in the **frontend** (JSZip); store the pieces in the DB and serve them
   without any server-side zip handling.
4. Add an **Update sifront** button in the admin Sifronts page: pick a new
   `.sifront`, unpack it client-side, and `PATCH` the existing entry's
   bundle/meta/version (no new row).
5. Show the bundle version in the sifront list.

Non-goals for v1: signed bundles, remote sifront registry/manifest, incremental
patches, per-asset caching/CDN, running multiple sifronts at once.

---

## 2. Container format (`.sifront` = ZIP)

| Entry | Required | Content |
| --- | --- | --- |
| `meta.json` | yes | UTF-8 JSON, see §3 |
| `bundle.js` | yes | Self-contained ES module (CSS injected, fonts inlined) |

`bundle.js` carries the whole app: the Vite JS output with the extracted CSS
prepended as a tiny runtime injector, so the ZIP stays two files.

```js
/* prepended by buildfront.php */
(() => {
  const css = "<inlined css; url(...) rewritten to data: URIs>";
  const style = document.createElement("style");
  style.dataset.sifront = true;
  style.textContent = css;
  document.head.appendChild(style);
})();
/* … raw Vite app bundle … */
```

The **theme bootstrap** (the `localStorage.theme` → `.dark` snippet that must
run before first paint) is **not** in `bundle.js`, because a `type=module`
script is deferred. It moves into the HTML shell generated by the backend (§6).

### Why frontend unpacking

- The deployed PHP may not have the `zip` extension (`ZipArchive` is absent
  here), and `PharData` requires a filename with a recognized extension, which
  uploaded temp files don't have.
- The admin already has to handle the file; JSZip unpacks it once, in the
  browser, and posts plain strings. The backend stays a dumb store.
- `buildfront.php` (a build-time CLI, not the served artifact) still writes the
  ZIP with `PharData(..., Phar::ZIP)`; and it also writes plain
  `<name>.bundle.js` / `<name>.meta.json` companions so the dev disk fast-path
  never opens a ZIP either.

## 3. `meta.json` schema

`meta.json` is the sifront's identity + theme contract. Authors keep the
`require_keys` list they have today; the build **injects** identity fields from
`package.json` and the build environment.

```jsonc
{
  "schema": 1,
  "name": "sifpress1",          // injected: package dir name
  "title": "Sifpress",          // optional author field (defaults to name)
  "version": "1.0.0",           // injected: package.json "version"
  "built_at": "2026-09-20T…Z",  // injected
  "entry": "bundle.js",         // injected
  "require_keys": [ /* unchanged, see plan/sifront-theme-kv-config.md */ ]
}
```

- Build merges `{schema,name,title?,version,built_at,entry}` over `meta.json`
  (author values win for non-injected keys; identity fields are authoritative).
- At runtime the sifront still reads the whole object as `SifrontMeta`;
  `parseSifrontMeta()` only looks at `require_keys`, so extra fields are inert.

## 4. Storage model

Migration `migrations/0019_sifront_bundle.sql`:

```sql
ALTER TABLE sifronts ADD COLUMN bundle BLOB;               -- bundle.js bytes
ALTER TABLE sifronts ADD COLUMN bundle_size INTEGER NOT NULL DEFAULT 0;
```

- `content` is **kept** for legacy HTML sifronts (pre-ZIP) and stays the
  fallback (§7).
- `meta`/`version` keep their roles; `version` now stores the semver string
  from `meta.json`.
- A sifront is "bundled" iff `bundle_size > 0`.
- `list`/`get` return `has_bundle` + `bundle_size`.

## 5. Build pipeline (`buildfront.php`)

Per sifront package:

1. `pnpm run build:dev|release` (unchanged).
2. Read `dist/index.html` to locate the app `<script src="assets/index-*.js">`
   and `<link rel=stylesheet assets/index-*.css>`.
3. Inline `url(...)` assets (fonts) in the CSS as `data:` URIs via the shared
   `inline_css_urls()` helper (`build_common.php`).
4. `bundle.js` = CSS-injector preamble + app JS (dev keeps the source map as a
   data URI).
5. `meta.json` = author `meta.json` merged with injected identity (§3).
6. Write `dist/<name>.sifront` with `PharData(..., Phar::ZIP)` (`meta.json`
   first, then `bundle.js`), **and** the dev companions
   `dist/<name>.meta.json` / `dist/<name>.bundle.js`.

`build.php` (the PHP artifact) is untouched.

## 6. Serving

### HTML shell (`serve_sifront_page`)

The backend stops echoing a stored HTML document and generates a fixed shell,
parameterized by the active sifront's `meta.json`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>{meta.title ?? name}</title>
  <script>/* theme bootstrap: localStorage.theme → html.dark */</script>
  <meta name="sifront_meta" content="{json-escaped meta.json}">
  <script type="module" src="?p=sifpress/asset/js/ui-sdk.mjs"></script>
  <script type="module" src="?p=sifpress/sifront-bundle&id={id}&v={version}"></script>
</head>
<body><div id="root"></div></body>
</html>
```

- `apply_ui_sdk_version()` adds the `&v=` to the ui-sdk tag; `base_url_meta()`
  is injected into `<head>` as before.
- The built-in construction sifront (`sifpress_in_construction`, `is_virtual`)
  has no bundle: its row is served via the construction fallback. A real theme
  is injected through the normal admin flow.

### Bundle endpoint (`?p=sifpress/sifront-bundle`)

`serve_sifront_bundle()` (in `spa.php`), routed from `router.php`:

- `id` optional; defaults to the active sifront.
- Streams the stored `bundle` BLOB (no dev disk override).
- Headers: `Content-Type: text/javascript; charset=utf-8`,
  `Cache-Control: public, max-age=31536000, immutable` (URL is versioned),
  `X-Content-Type-Options: nosniff`; `no-cache` in dev. 404 when absent.

---

## 7. Legacy compatibility

- If `bundle_size > 0`, serve the shell + bundle endpoint.
- Else if `content` is non-empty, serve it verbatim exactly as today.
- Else the construction fallback HTML.

## 8. Create / update API

No dedicated upload endpoint. The admin UI unpacks the ZIP and calls the
existing JSON actions (permission **`sifronts.manage`** — fixing the old
`settings.manage` mismatch):

```jsonc
POST  ?p=sifpress/api&action=sifronts.create
PATCH ?p=sifpress/api?action=sifronts.update
{
  "name": "sifpress1",        // create: required; update: optional rename
  "id": 1001,                  // update only
  "version": "1.0.0",          // from meta.json
  "meta": { "require_keys": [ /* … */ ] },
  "bundle": "(()=>{…})();\n…"  // bundle.js contents (≤ SIFRONT_MAX_BUNDLE_BYTES)
}
```

- `create`/`update` set `bundle`, `bundle_size = strlen(bundle)`, `meta`,
  `version` alongside the existing `name`/`content` fields; they reject a
  `bundle` over 8 MiB.
- `update` no longer auto-increments the version (semver is bundle-owned).
- `sifronts.upload` was removed (it forced a server-side ZIP read).

---

## 9. Admin UI

- `admin_ui` gains `jszip`.
- `admin_ui/src/lib/sifront-bundle.ts`: `readSifrontBundle(file)` →
  `{ name, version, meta, bundle }` (requires both entries, validates
  `meta.json`).
- `admin_ui/src/pages/sifront.tsx`
  - "New sifront" reads the picked `.sifront` and `sifrontsApi.create(...)`.
  - Each card's **Update** button reads the picked file and
    `sifrontsApi.update({ id, ... })`.
  - Toasts show the resulting version; the list already renders it.
  - The `content`/legacy path is dropped from the UI.
- `ui_sdk/src/pages.ts`: `sifrontsApi.create` / `update` accept `bundle`;
  `SifrontListItem` carries `has_bundle` / `bundle_size`.
- i18n (`en` + `zh`): `sifront.update`, `updated`, `updateFailed`.

---

## 10. Security / limits

- Create/update gated by `sifronts.manage`; only admins hold it by default.
- `SIFRONT_MAX_BUNDLE_BYTES` (8 MiB) caps the posted `bundle` (validated
  server-side; `post_max_size` bounds the body before app code).
- JSZip parses an admin-chosen file in the admin's own browser; the result is
  plain strings validated by the API.
- Serve `bundle.js` with `nosniff` + JS content type; the shell is generated
  server-side (no user-controlled HTML).
- `meta.json` is embedded in the shell via `htmlspecialchars(..., ENT_QUOTES)`
  over a `json_encode` using `JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT`.

---

## 11. Verification

- `php build.php` / `php buildfront.php` → `dist/sifpress1.sifront` is a ZIP
  with `meta.json` + `bundle.js`, plus the `.bundle.js` / `.meta.json`
  companions.
- Dev `./dev.sh`: `/` renders from the companions + `sifront-bundle`; CSS
  applied, no FOUC.
- Admin: New/Update unpack a `.sifront` and create/update a row; list shows the
  new version; the active page serves it.
- Legacy: an HTML `content` row with no bundle still renders.
- `pnpm run typecheck` (admin_ui + ui_sdk + sifpress1), formats, builds clean.
- Curl: `sifronts.create`/`update` with `bundle` set `has_bundle`/`bundle_size`
  and serve via `sifront-bundle`; oversized bundle → 422.

---

## 12. Decisions taken

1. **CSS placement** — inlined into `bundle.js` (exactly two entries).
2. **Original ZIP** — not stored; only the extracted pieces are kept.
3. **Legacy rows** — served verbatim, no migration.
4. **Version conflicts** — allowed; the UI reports the resulting version.
